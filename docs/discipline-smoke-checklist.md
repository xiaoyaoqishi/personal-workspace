# 自律养成验收

- `npm ci`（`frontend-discipline`），`python3 -m pytest -q backend/tests/test_discipline.py`，`bash scripts/check_all.sh`。
- 使用 `./dev.sh up`；首页自律卡片进入 `/discipline/`，点击日期打开只读侧边抽屉，URL 不变；切换月份后打开日期，关闭抽屉应保持月份与滚动位置。资源位于 `/discipline/assets/`。
- `/discipline/plan` 固定当天，无日期控件、“今天”、“调整当天”和“保存记录”按钮。修改评价、统计开关和备注后约 650ms 自动保存；已保存后刷新保留。
- 修改默认作息新增时段后，当天立即增加，原有评价及具体记录保留；历史快照不变。修改模板本身不隐式创建当天记录。
- 默认作息重叠、空主题及倒置时间被拒绝，并指出具体原因；新增时段优先填补空档，末段为 23:00 或 23:59 时仍不得生成无效时间。没有空档时禁用新增。
- 删除已有评价或备注的时段后，当天立即移除该卡片，原内容可在调整记录的同步前快照查看。删除后在相同时间新增另一时段可正常保存，新段未评价、空备注，不继承旧段结果。保留时段评价备注和历史快照不变。清空评价仍可选择“尚未评价”。
- 连续输入、前一次请求未完成时继续修改，较旧响应不得覆盖新输入；按顺序使用新 revision 保存。断网或 409 时保留输入并提示失败，可重试；离开内部链接先等待保存，保存失败时停留原页；直接刷新或关闭尚未保存页面应提示。
- `npm test --prefix frontend-discipline` 覆盖自动保存排队、失败保留与重试、重复 flush；`check_all.sh` 包含这些检查。
- 两个普通用户记录互不可见；无模块权限返回 403，只读用户可查看但不能保存或修改模板。
- 屏幕统计侧栏进入 `/discipline/screen`，AI 总结进入 `/discipline/ai`。验收分别见 `docs/discipline-screen.md`、`docs/discipline-ai.md`，四套主题、紧凑布局及窄屏均需检查；AI 首次生成、依据、日／周、历史版本、偏好和刷新均需验证。
- 日期抽屉宽度最多 640px 且不超过视口 78%，窄屏也留出首页可见区域；参与统计的时段在抽屉与每日计划使用整卡绿/黄/红背景对应符合/部分符合/偏离，未评价及不统计保持中性。
- 默认作息设置展示历史/当天/未来的影响说明。“调整记录”可分页查看版本、北京时间、统计时段数，查看作息快照及调整前作息、当天同步前后评价与备注快照。
- 成功修改追加版本；后续再修改当天评价或模板不得改变已保存的快照。失败或冲突不追加任何版本。旧模板保留当前版本基线，时间显示未记录，不伪造早期历史。
- 生产发布后检查 `/discipline` 重定向、`/discipline/` HTTP 200、静态资源与 SPA 回退。生产验收应额外包含新入口。

## 统计与当日锁定

- 仅勾选的时段参与分母：100/50/0 等权平均，未评价计 0。准确测试 75%、40%、37.5% 等阈值，未选任何时段显示不统计。
- 午休与晚饭默认不选；开关可在默认作息及当天卡片调整，保存后刷新保持。
- 日历绿/黄/红分别为良好/待改进/失败，并配文字；周末、节假日为灰色。月均值只包含有效统计日，未来及首次记录前不计入；首次记录后漏记历史工作日计 0。
- 2026-09-25、2027-06-09 节假日不计；2026-10-10、2027-05-08 调休周六也不计；未知年份提示假期表未维护，不产生错误成绩。
- 直接调用 PUT 修改昨天或明天（含时段、备注、included）必须 403，即使管理员或 DEV_MODE 也禁止。保存冲突 409 不覆盖。
- 模拟北京时间午夜：当天变为只读，保存请求由后端拒绝；修改系统显示时区无法绕过服务器规则。
- 假期依据：[2026 国务院通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)、[2027 国务院通知](https://www.gov.cn/zhengce/content/202611/content_7085101.htm)。后续按年度维护 `backend/services/discipline_calendar.py`，不新增依赖。
